# template-v3

Go + SvelteKit starter template. Backend: **huma v2** (OpenAPI-first) + **chi router** + **sqlc** + **pgx**. Frontend: **SvelteKit SPA** + **TanStack Query** + **@hey-api/openapi-ts** (typed client generated from OpenAPI spec).

## Architecture

```
cmd/
  server/        — main binary (chi + huma wired, DB pool, migrations)
  gen-spec/      — generates openapi.json without a DB connection

internal/
  auth/          — OTP login, session tokens, auth middleware
  apikey/        — API key CRUD + request middleware
  user/          — /api/users/me
  company/       — company CRUD + member management
  featureflag/   — flag reads (user) + admin upsert
  platform/
    deps.go      — shared Deps struct (chi.Router, huma.API, Queries, …)
    humax/       — auth helpers (RequireAuth, RequireSelectedCompany, error helpers)
    httpx/       — chi middleware (request logger, JSON helpers)
    compiled/    — sqlc-generated queries + models
    migration/   — embedded SQL migrations

frontend/
  src/
    lib/api/     — generated SDK (sdk.gen.ts, types.gen.ts) — do not edit
    lib/api-client.ts — configures the client (base URL, auth header, 401 redirect)
    routes/app/  — authenticated pages
    routes/(auth)/ — login/verify pages
```

## Key development commands

```bash
make run                        # start Go server on :8080 (reads .env)
make gen                        # sqlc + openapi.json + TypeScript SDK
make build                      # gen → frontend build → bin/server
make check                      # go vet + JSON tag lint + tsc
make migrate name=add_foo_to_bar  # create a new migration pair
```

Frontend (in `frontend/`):
```bash
bun run dev       # Vite dev server on :5173 (proxies /api → :8080)
bun run check     # svelte-check — target: 0 errors
```

## Backend: huma handler pattern

Every handler lives in a feature package (`internal/<feature>/handler.go`).

**Types** (`types.go`) — Input/Output wrapper structs huma uses for schema generation:
```go
type CreateThingInput struct {
    Body CreateThingRequest
}
type CreateThingOutput struct {
    Body ThingInfo
}
```

**Handler** (`handler.go`):
```go
func (h *Handler) handleCreate(ctx context.Context, input *CreateThingInput) (*CreateThingOutput, error) {
    p, err := humax.RequireAuth(ctx)   // returns 401 if not authenticated
    if err != nil {
        return nil, err
    }
    // ... use h.queries and input.Body
    return &CreateThingOutput{Body: result}, nil
}
```

**Register** (`setup.go`):
```go
huma.Register(deps.API, huma.Operation{
    OperationID: "create-thing",
    Method:      http.MethodPost,
    Path:        "/api/things",
    Summary:     "Create a thing",
    Tags:        []string{"things"},
    Security:    humax.BearerAuth(),
}, h.handleCreate)
```

**Error helpers** (`internal/platform/humax/errors.go`):
```go
humax.NotFound("thing not found")      // 404
humax.Conflict("already exists")       // 409
humax.Forbidden("not allowed")         // 403
humax.Unprocessable("invalid state")   // 422
humax.BadRequest("bad input")          // 400
humax.Unauthorized("not logged in")    // 401
```

**Auth helpers**:
```go
p, err := humax.RequireAuth(ctx)                  // authenticated user
p, err := humax.RequireSelectedCompany(ctx)       // user + company selected
// p.UserID, p.SelectedCompanyID int64
```

## Backend: adding a feature module

1. Create `internal/<feature>/` with `types.go`, `handler.go`, `setup.go`
2. Call `setup.Setup(ctx, deps)` in `cmd/server/main.go`
3. Also call it in `internal/platform/routes/routes.go` (used by `gen-spec`)
4. Run `make gen-spec && make gen-client` to regenerate the TypeScript SDK

## Frontend: using the generated SDK

The SDK lives in `frontend/src/lib/api/`. Import from `$lib/api-client.js`:
```ts
import { listThings, createThing } from '$lib/api-client.js';
```

Types come from `$lib/api/types.gen.js`:
```ts
import type { ThingInfo } from '$lib/api/types.gen.js';
```

**Never edit files in `src/lib/api/`** — they are regenerated by `make gen-client`.

## Frontend: TanStack Query pattern

```ts
const query = createQuery({
    queryKey: ['things'],
    queryFn: () => listThings().then((r) => r.data?.things ?? [])
});

const mut = createMutation({
    mutationFn: (body: CreateThingRequest) => createThing({ body }),
    onSuccess: () => qc.invalidateQueries({ queryKey: ['things'] })
});
```

Access in template: `$query.data`, `$query.isLoading`, `$mut.isPending`.

## Database: adding a query

1. Add SQL to `internal/platform/migration/sql/` (new migration) or a `.sql` query file
2. Run `make sqlc` to regenerate `internal/platform/compiled/`
3. Use `deps.Queries.YourNewMethod(ctx, params)` in handlers

## Code conventions

- JSON tags use **camelCase** (`json:"createdAt"`) — snake_case is rejected by `make check`
- Feature packages **do not import each other** — cross-domain imports are rejected by `make check`
- No comments unless the WHY is non-obvious
- Auth is enforced per-handler via `humax.RequireAuth(ctx)`, not via global middleware
- CORS is hardcoded `*` (intentional for this template)
- `openapi.json` at repo root is committed — regenerate with `make gen-spec` after any handler/type change
